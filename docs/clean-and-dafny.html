What each system is trying to do

Clean makes mathematical declarations readable and translates their meaning into Lean. Dafny combines a programming language with specifications and automated verification. For Clean’s CLR-style algorithm examples, Dafny is a useful design comparison; for the magnetic-matrix study, the existing Lean mathematical environment is the more direct foundation.

Compare three artifacts separately: a statement, its proof, and an executable implementation. A generated Clean result currently defines a Lean Prop. It does not prove that proposition. A Dafny lemma with a successfully verified body establishes its contract under the verifier’s assumptions. A method additionally describes computation.

Dafny facts here use the official documentation’s Dafny 4 conventions. The main reference URL identifies itself as a development version; this is not a pinned release compatibility test. No Dafny executable is installed in this workspace, so the following snippets have not been run.

The dangerous false friend: Assume

Clean — existing declaration forms; local source required

Import "../library/types.clean"
Import "../library/sources.clean"

Result positive successor:
  Attribution: local; positive successor; original
  Let x: Real
  Assume positive: x > 0
  Conclude: x+1 > 1

Dafny 4 — illustrative lemma

lemma PositiveSuccessor(x: real)
  requires x > 0
  ensures x + 1 > 1
{
}

The logical statement is ∀x, x > 0 → x + 1 > 1. Clean’s Assume corresponds to Dafny’s requires here. Dafny’s statement assume x > 0; instead tells the verifier to accept a fact without proving it at that point. Translating Clean hypotheses to such statements would obscure the contract.

An empty lemma body {} still asks Dafny to prove its postcondition. Omitting the body is not equivalent to supplying a proof. The Clean local source must be declared in the surrounding file; the snippet is a declaration fragment. Dafny reference: specifications and assume statements.

Definitions and named conditions

Clean — existing forms; types imported

Define successor(x: Real): Real:
  Equals: x+1

Condition positive(x: Real):
  Holds when: x > 0
  Assumption name: positivity of {x}

Dafny 4 — illustrative definitions

function Successor(x: real): real {
  x + 1
}

predicate Positive(x: real) {
  x > 0
}

Clean’s condition denotes a Lean proposition; Dafny’s predicate is Boolean-valued logical vocabulary. The author-facing similarity is strong, but Lean Prop and Bool must not be conflated. Dafny also distinguishes compiled functions from ghost function declarations used only for specification. Clean currently has no matching general execution/ghost classification.

Keep conditions as reusable mathematical definitions and let explicit hypotheses use them. Automatically generated hypothesis names are presentation and binding machinery, not additional mathematics. Dafny reference: functions and predicates.

Sorting: specify both order and preservation

A sorting contract needs both sortedness and preservation of the input multiset. Merely returning a sorted sequence permits the empty sequence as an incorrect implementation. Dafny has immutable sequences and multisets suitable for expressing these two obligations. Dafny collection types.

Clean — proposed specimen

-- Proposed; not accepted by the current compiler.
Result insertion sort correctness:
  Attribution: local; insertion sort; original
  Let xs: List(Integer)
  Let ys = insertion sort(xs)
  Conclude:
    sorted(ys)
    and multiset(ys) = multiset(xs)

Lean — statement shape

predicate Sorted(s: seq<int>) {
  forall i, j ::
    0 <= i < j < |s| ==> s[i] <= s[j]
}

// Contract sketch only: implementation omitted.
method InsertionSort(s: seq<int>) returns (t: seq<int>)
  ensures Sorted(t)
  ensures multiset(t) == multiset(s)

The Dafny method above is deliberately only a contract, not a verified implementation. Clean’s authored insertion-sort and heapsort specimens likewise remain proposed: see the sorting study. A future implementation must define the algorithm independently of the desired theorem, then prove these properties.

For an in-place array algorithm, Dafny adds a modification frame such as modifies a, pre-state references such as old(a[..]), and loop invariants. Clean needs an explicit state model before borrowing that surface syntax; a pure function on sequences would be a smaller first step. Dafny quick reference.

Termination, cost, and proof automation

A decreasing measure establishes termination, not a runtime bound. For an O(n log n) heapsort claim, name the measured operation, instrument its count, establish a bound, and separately derive the asymptotic statement. Dafny’s decreases annotations support termination proofs; certain executable constructs can opt out with decreases *. Termination tutorial.

Clean’s existing independent Lean heapsort study counts key comparisons. Its bound is not a statement about wall time or allocation. A future Clean cost interface should make the distinction visible in the theorem’s name and hypotheses.

Dafny uses Z3 to discharge verification obligations. Extra lemmas and carefully scoped facts can make verification more reliable; a timeout is not a counterexample. Verification optimization. Lemmas can decompose an inductive argument and are erased from executable code. Lemmas and induction.

Lean checks elaborated proof terms in its kernel. Clean’s current front end emits statements and relies on separate Lean proof work. Its unique-parse and unique-target requirements constrain the meaning of a declaration; they do not demand a unique mathematical proof or prohibit automated proof search. A future SMT integration would need an explicit trust policy and must never silently turn failure into an assumed theorem.

What to borrow, and what to keep explicit

ConcernDafny comparisonRecommendation for Clean
Contractsrequires / ensuresKeep Assume / Conclude; give future algorithms explicit contracts.
Statereads / modifies / oldStart with pure definitions. Specify heap and state semantics before imperative syntax.
Proof structureLemmas, assertions, loop invariantsSeparate statement authoring from a future proof language.
TerminationdecreasesRequire a well-founded argument for recursive definitions; keep cost separate.
Mathematical vocabularyModules, types, predicates, functionsRetain explicit imported Clean modules. A pretty name needs a real definition.
Readable publicationComments and documentationKeep attribution, Text blocks, and LaTeX rendering as first-class authoring features.

The first four rows draw on the official quick reference; the recommendations are design judgments, not adopted language changes. Dafny is not a drop-in proof backend for Mathlib theorems. Porting the matrix or topology studies would also require mathematical representations and supporting results.

The most useful next experiment is the same small pure insertion-sort implementation in both systems, with sortedness, multiset preservation, termination, and an explicit comparison count. Record definition effort separately from proof effort. Today’s report does not pretend that either the proposed Clean program or a bodyless Dafny contract constitutes that experiment.
