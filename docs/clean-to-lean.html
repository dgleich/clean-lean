The record identifier is schematic. Field/module structures are explicit values; subspaces retain their scalar and ambient-space identities. Implemented subset

-- Equivalent last clause:
-- Let p: Path(X,t,x,y)

Lean binder shape

∀ (X : Type) (t : TopologicalSpace X)

The constructor grammar already parses the application. Ordered parameter types then classify and check its arguments. Named value indices preserve their bound Lean locals. No topology is inferred. Calls with dependent argument and result types

Implemented subset

Clean — paths module imported

Let q = reverse path(t,x,y,p)
-- q has type Path(X,t,y,x)
Conclude: reverse path(t,y,x,q) = p

Lean call shape

-- Wrapper body: @Path.symm X t x y p
let q : @Path X t y x := @reversePathWrapper X t x y p

The wrapper identifier above is schematic. The translator infers X by structural matching and supplies it explicitly. Indices use actual local bindings, including fresh quantified locals. Scoped quantified conditions

Implemented

Clean

for every (x: Real,
  there exists (y: Real, x = y))

Lean equivalent

∀ (x : ℝ), @Exists ℝ (fun (y : ℝ) => x = y)

The final parenthesis ends each scope; a comma outside it may separate assumptions. Domains are explicit and bodies must be conditions. Keywords are case-insensitive; shadowing is rejected. Nested domain types refer to the correctly renamed outer locals. LaTeX uses English “for every” and “there exists”.

The contract specifies exact grammar and translation. The working topology study authors images and continuity with these forms. Six independent canonical target checks cover this slice; inherited general elaboration obligations remain pending.

Assume introduces a proof parameter

Implemented

An assumption contributes an implication or dependent proof binder to the generated proposition.

Clean

Assume nonzero: x ≠ 0
Assume eigenpair: A*x = μ*x
Conclude: x ≠ 0 and A*x = μ*x

Lean

∀ (nonzero : x ≠ 0)
  (eigenpair : A *ᵥ x = μ • x),
  x ≠ 0 ∧ A *ᵥ x = μ • x

These are statement fragments under previously introduced parameters. The next-language draft gives assumption labels a separate namespace; they are not proposition-valued variables. The prototype has known debt in that distinction. English labels with spaces are a draft feature, not generally implemented.

Implemented

Clean

  Returns: Complex

  Render latex: \det({A})

Proposed

A proposed summation form introduces a local variable and supplies a scoped body to a finite sum.

Clean

Lean

Finset.sum S (fun v => degree G v)

-- Familiar Lean notation:
∑ v ∈ S, degree G v

Multiple binders expand in source order

Proposed

The proposed multi-binder sum expands to nested sums. An earlier binder is visible in later domains and the final body.

Clean

sum(u in S, v in complement(G,S);
  adjacency(G,u,v))

Lean

Finset.sum S (fun u =>
  Finset.sum Sᶜ (fun v => adjacency G u v))

For the displayed graph example, both variables range over Fin n; complement is relative to that finite vertex universe. A binder is not visible in its own domain or outside the expression. These are proposed binding rules that still need the full grammar and acceptance fixtures.

Implemented

Provenance and presentation accompany a declaration without becoming logical assumptions.

Render latex: M({A},{q})

The last two lines illustrate fields in their respective containing declarations, not one complete block. Bibliographic citation keys become source keys. The acceptance contract

For a fixed source and explicit, pinned environment, accepted input must have one parse and one fully elaborated Lean target and type. Inferred coercions, instance arguments, universe instantiations, and proof arguments count. A term that merely compiles is insufficient.

Distinct parses are syntax ambiguity; distinct permitted targets are semantic ambiguity. Resource exhaustion is incomplete analysis, not a successful choice. See the normative acceptance requirements and pending acceptance cases. The prototype is not certified as conforming.

This HTML is the maintained explanatory map, not a competing grammar. Authority: target syntax and semantics · current prototype · decisions · paper definitions and translations.

Maintenance: every syntax or translation change updates its mapping, status, scope notes, and Lean target here. New binding forms remain proposed until their parse and translation contracts are complete. No network requests, external assets, or build step are required to read this file.
