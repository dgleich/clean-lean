# Result identifiers in generated Lean

Every accepted result title continues to use the existing normalized identifier:
English word separators become underscores, case and supported Unicode are
preserved, and normalized collisions reject. Generation now emits that identifier
between Lean guillemets, for example `Result example` becomes
`def «example» : Prop :=` inside namespace CleanStatements.

The quote marks are lexical delimiters, not part of the Lean Name. The native
name is still exactly the two components CleanStatements and the normalized
identifier. No keyword blacklist, keyword-dependent rename, import-order decision,
or extra suffix is used. Ordinary references such as
`CleanStatements.ordinary_result` continue to work. Keyword references may be
written `CleanStatements.«example»`.

Grammar, parsed theorem trees, attribution, source names and LaTeX titles are
unchanged. Existing title validation excludes the quote delimiter from accepted
identifiers, so the quoted spelling has exactly one lexical interpretation.
Existing collision checks run before emission; quoting cannot distinguish titles
that previously normalized to the same identifier. This fixes the actual Lean
parser failure exposed by the projected-condition fixture.
