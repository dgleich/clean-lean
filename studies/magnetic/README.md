# Magnetic matrices: five study artifacts and a common library

The four Lean files each include the definitions they need and import only Mathlib.
The authored Clean file imports [Common.clean](../../library/Common.clean), a temporary
standard library containing types, finite operations, and the imported Hermitian
condition. Its paper-specific definitions remain in the study. No file imports a
project Lean helper module. The Clean source contains definitions and statements,
but no proofs. `Common.clean` is the one explicit standard Clean dependency.

| File | Purpose |
| --- | --- |
| [Reference.lean](Reference.lean) | Independently authored Lean definitions, theorems, and proofs |
| [Statements.lean](Statements.lean) | Independently authored Lean definitions and theorem statements only |
| [Statements.clean](Statements.clean) | Paper-specific definitions and six theorem statements; imports Common.clean |
| [Generated.lean](Generated.lean) | Lean statements translated directly from the Clean source |
| [Verified.lean](Verified.lean) | The generated Lean statements plus complete proofs and definition-agreement lemmas |

The two statement-only Lean files declare named propositions (`def … : Prop`).
They do not assert axioms or use `sorry` to masquerade as proofs.
`Generated.lean` and `Verified.lean` are regenerated by [verify.py](verify.py).
The latter embeds the reference proof text, so it also compiles as a single file.
The Lean files share a pinned Lean 4.24.0 / Mathlib installation. The Clean source
also imports the placeholder standard library, which the generator expands into each Lean output. The generator itself uses the repository's Clean compiler.

## Mathematical coverage

The source is Huang, Gleich, and Li,
[*Powers of Magnetic Graph Matrix: Fourier Spectrum, Walk Compression, and Applications*,
arXiv:2506.07343v1](https://arxiv.org/html/2506.07343v1).
The principal proved result is the **forward** part of Theorem 1, equation (17):

\[
M(A,q)^m=e^{-2\pi iqm}\sum_{k=0}^{m}e^{4\pi iqk}\Phi(A,m,k).
\]

Here `M(A,q)=exp(2πiq) A + exp(-2πiq) Aᵀ`. A is any finite real square matrix,
q is real, and m is any natural number. Dimension zero, signed weights, and self
loops are permitted for this algebraic identity. The profile sums ordered products
of m choices of A or Aᵀ with exactly k forward choices. Factors are never commuted.

The other statements are supporting results and one counterexample, not additional
numbered theorems of the paper:

- the magnetic adjacency is Hermitian;
- the unnormalized magnetic Laplacian is Hermitian;
- zero potential gives A + Aᵀ;
- the two-step mixed profile is A Aᵀ + Aᵀ A;
- the displayed v1 inverse formula fails at the length-one endpoint.

Our supporting Laplacian convention is `L(A,q)=D(A)-M(A,q)` with
`D(A)[i,i]=sum_j(A[i,j]+A[j,i])`; self loops contribute twice. No normalized
Laplacian or positive-semidefiniteness theorem is claimed here. The full inverse
transform, compression claims, and spectral results are not formalized.

## What the Clean file now defines

The phase, adjacency, degree diagonal, Laplacian, direction-word enumeration,
ordered word product, walk profile, and Fourier sum all use `Define … Equals:`.
The principal statement also writes out its phase-weighted sum explicitly.

Finite words are constructed using a list of direction choices at each position.
Generic `choices`, `map`, `filter`, `ordered product`, `sum matrices`, and
`sum before` operations expose standard Mathlib list and finite-sum operations.
Their `Means` fields contain no paper-specific definitions. The imported `Condition Hermitian` uses the standard
Mathlib `IsHermitian` predicate; it is a `From Lean` condition in Common.clean. The new bounded
[`function(x: T, body)` form](../../docs/function-expressions.md) supplies scoped
functions to these operations. It is a working explicit spelling, not a claim
that the proposed natural-language sum syntax is implemented.

The generic enumeration and the independent Lean reference enumerate words in
different orders. The agreement proof establishes a permutation, then transports
it through filtering, mapping, and summation. This preserves multiplicity while
keeping the order of matrix factors within each word unchanged. Further agreement
lemmas identify the Clean-authored phase, profile, Fourier sum, adjacency, and
Laplacian with the independent reference definitions. The proofs then inhabit the
actual generated propositions.

## A source boundary case

At m = 1, the sum in v1 equation (24) is empty and q₀=0. For k=1 the formula would
reconstruct A as `(A+Aᵀ)/2`. For the directed single edge
`A = [[0,1],[0,0]]`, the correct (0,1) profile entry is 1, while that formula gives
1/2. Both the Lean reference and the Clean-derived verification prove this
inequality. The forward identity is unaffected.

The even-length DFT associated with odd m has a Nyquist endpoint. The source's
reduced inverse expression needs that endpoint resolved before it can be ported as
an unrestricted theorem. This finding concerns the displayed formula in pinned v1;
it does not claim to describe every reconstruction method or later manuscript.

## Reproduce

Run from the repository root. All four Lean files can be checked independently;
no build of a project mathematics module is needed.

```sh
python3 studies/magnetic/verify.py
lake env lean studies/magnetic/Reference.lean
lake env lean studies/magnetic/Statements.lean
lake env lean studies/magnetic/Generated.lean
lake env lean studies/magnetic/Verified.lean
LAKE=lake python3 tools/check_function_targets.py
python3 -m unittest discover -s tests -v
pdflatex -interaction=nonstopmode -halt-on-error -output-directory studies/magnetic/generated studies/magnetic/latex/magnetic.tex
pdflatex -interaction=nonstopmode -halt-on-error -output-directory studies/magnetic/generated studies/magnetic/latex/magnetic.tex
python3 tools/provenance.py --apply
python3 tools/build_review.py
python3 tools/provenance.py
```

The [PDF](generated/magnetic.pdf) and [review browser](../../docs/review.html) are
reading aids. Lean checks the proofs; the browser itself does not. The reported
axioms of the forward proof are standard Lean/Mathlib `propext`, `Classical.choice`,
and `Quot.sound`, with no `sorryAx`, added paper axioms, or `native_decide`.
